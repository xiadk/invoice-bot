# invoice-bot 使用说明

> 1688 采购发票催收工具：把订单/发票数据存进 MySQL，看板按商家统计待开票与已开票金额，一键给卖家批量发送催收消息。
>
> 本版本已完成二次开发：**取消了看板的「提交开票申请」功能与按钮**，数据源**从本地 JSON 改为 MySQL 数据库**，并新增「名称映射」页用于维护税务局销方名称与 1688 商家名称的对应关系。
>
> **2026-10-13 重大调整**：① **服务器不再保存 1688 登录态、不再启动服务器浏览器发送** —— 催收消息只在你**自己电脑**上发送；② 「重新导入数据」改为**增量导入**：按订单号/行哈希去重，数据库已有的跳过、只插入新数据。
>
> **2026-10-14 变更（发送通道迁移）**：发送通道从「浏览器扩展 + 税号配对」升级为「**本机桌面助手（催收小助手，Windows）**」——看板点「绑定本机助手」即可用深链自动绑定（**不再使用税号当配对码**，改为一次性令牌换取本机设备令牌），旧扩展下载接口已下线（返回 410）。本文档中「扩展 / chrome://extensions / 配对码 / 税号配对」相关描述请以 **[《本机助手安装与迁移指引》](./助手安装与迁移指引.md)** 为准。
>
> **代码仓库**：https://github.com/xiadk/invoice-bot.git

## 两种部署方式，按场景选

| 场景 | 方式 | 文档 |
|---|---|---|
| 自己一台电脑用，数据在本机 | Windows 本机部署（Node + 便携 MariaDB） | 本文「新电脑部署指南」 |
| 放云服务器，多人浏览器访问 | Docker 一键部署（应用 + MariaDB 容器） | 部署文档已移除（命令见文末「命令速查」） |

两种方式数据互不相通：要迁移就把本机库 dump 出来，手动恢复到目标库。
发送通道完全一样——都在各自电脑的**本机助手**里执行，服务器不碰登录态。

## 新电脑部署指南（从零开始，裸机可照做）

适用场景：把项目搬到一台**什么都没装的全新 Windows 电脑**。全程约 40~50 分钟。

### 第一步：安装 Node.js（约10分钟）

1. 打开官网 `https://nodejs.org/zh-cn`，下载 **LTS 长期支持版**（v20 或更高）
2. 双击安装包，一路「下一步」默认安装（安装路径不要含中文和空格更稳妥）
3. 验证：按 `Win+R` 输入 `cmd` 回车，打开黑色命令行窗口，输入：
   ```
   node -v
   ```
   显示 `v20.x.x` 之类的版本号即成功。若提示"不是内部或外部命令"，重启电脑再试；仍不行说明安装时没勾选 PATH，重装一遍勾上「Add to PATH」

### 第二步：设置 npm 国内镜像（必须，否则装包卡死）

```
npm config set registry https://registry.npmmirror.com
```

没有报错即成功（国内直连国外 npm 源会无限卡住，这是必做项）。

### 第三步：安装 MySQL 数据库（便携版，约10分钟）

本项目不再用 JSON 存数据，**没有数据库看板就是空的**。用官方绿色包最省事，不需要管理员权限、不需要安装程序：

1. 下载 MariaDB 11.4 便携包（MySQL 协议完全兼容，驱动也通用）：
   `https://mirrors.tuna.tsinghua.edu.cn/mariadb/mariadb-11.4.13/winx64-packages/mariadb-11.4.13-winx64.zip`
2. 解压到 `D:\mysql`（路径不要含中文/空格），解压后能看到 `bin\mysqld.exe`
3. 在该目录建一个 `my.ini`（把下面 4 处 D:\mysql 换成你的实际路径）：
   ```ini
   [mysqld]
   basedir = D:/mysql
   datadir = D:/mysql/data
   port = 3306
   bind-address = 127.0.0.1
   character-set-server = utf8mb4
   collation-server = utf8mb4_general_ci
   [client]
   port = 3306
   default-character-set = utf8mb4
   ```
4. 初始化数据目录（只需执行一次），命令行进入 `D:\mysql` 后执行：
   ```
   bin\mysql_install_db.exe --datadir="D:\mysql\data" --password=invoice123 --port=3306
   ```
   看到 `Creation of the database was successful` 即成功
5. 启动数据库：
   ```
   bin\mysqld.exe --defaults-file="D:\mysql\my.ini" --console
   ```
   再开一个命令行窗口验证：
   ```
   bin\mariadb.exe -h127.0.0.1 -uroot -pinvoice123 -e "SELECT VERSION();"
   ```
   能打印版本号即启动成功（这个窗口可以一直挂着，或按下面第六步改路径后直接用脚本启动）

> 已有现成 MySQL 服务器的话可跳过本步，只需把服务器地址/账号/密码填进 `config.json` 的 `mysql` 段。

### 第四步：复制项目文件

用 U 盘/局域网共享，把整个 `invoice-bot` 文件夹复制到新电脑，建议放在简单路径如 `D:\invoice-bot`（**避免中文路径和过深目录**）。

**必须复制的文件**：

| 文件/文件夹 | 说明 |
|---|---|
| 所有 `.js` 文件、`lib/`、`electron/`、`sql/`、`scripts/`、`docs/`、`dashboard.html` | 程序本体（本机发送通道由桌面助手 `electron/` 承担；旧 `extension/` 已于 2026-10-16 删除） |
| `data/完成订单/*.xlsx` | 订单数据源，丢了看板就是空的 |
| `data/已开票订单/*.xlsx` | 税务局全量发票导出，丢了已开票统计就是空的 |
| `package.json`、`package-lock.json` | 依赖清单 |
| `config.json` | 消息模板 / 发送参数 / 数据库配置（**开票抬头已改由数据库按账号维护**，见「系统管理 → 用户管理」），**含账号与数据库密码，不要通过聊天软件/网盘明文传输，用U盘** |

**不要复制的**（到新电脑重新生成更省事）：

- `node_modules/` —— 在新电脑重新安装
- `data/state-1688.json`、`data/users/*/state-1688.json` —— 历史遗留文件，程序已不再读取（服务器不保存任何登录态）；到新电脑只需装扩展重新配对，在自己浏览器里登录 1688 即可（见「本机浏览器通道」）
- `data/*.json` 其余数据文件 —— 不再需要（数据已入库）

### 第五步：安装项目依赖和浏览器内核（约5~10分钟）

命令行进入项目目录：

```
D:
cd D:\invoice-bot
```

依次执行：

```
npm install
```

```

npx playwright install chromium
```

（第一行设置浏览器下载镜像，第二行下载 Chromium 内核约 200MB；两行必须在**同一个命令行窗口**连续执行，因为 set 只对当前窗口生效）

### 第六步：改数据库路径并建库导数据

1. 用记事本打开 `scripts\mysql-start.bat` 和 `scripts\mysql-stop.bat`，把 `MYSQL_HOME` 改成你的 MySQL 目录（如 `D:\mysql`）
2. 确认 `config.json` 的 `mysql` 段是本机数据库信息（用户 root / 密码 invoice123 / 库 invoice_bot / 端口 3306）
3. 建库建表 + 导入数据：
   ```
   node import-to-db.js
   ```
   看到「建库建表完成 → 完成订单 xxx 单 → 已开票订单 xxx 行」即成功

### 第七步：验证环境

```
node --check server.js
```

无报错输出即环境正常。再手动打开普通浏览器访问 `https://www.1688.com`，确认新电脑网络能正常上 1688。

### 第八步：启动 + 配对本机浏览器

```
node server.js
```
→ 浏览器打开 `http://localhost:8787` → 用管理员账号登录 → 看到看板即部署完成。

**发送前的唯一准备（只做一次）**：催收消息从**你自己电脑的浏览器**发出，所以要在本机浏览器里安装扩展并配对：

1. 在你自己电脑的 Chrome / Edge 里打开 1688 并确认已登录（通常你本来就登录着）。
2. `chrome://extensions` → 开「开发者模式」→「加载已解压的扩展程序」→ 选项目里的 `extension/` 目录。
3. 看板右上角点「**配对指引**」→「**生成配对码**」，把**服务器地址 + 6 位配对码**填进扩展图标里的弹窗 → 点「连接」。
4. 看板顶部通道状态变绿（「已连接 · 1688 已登录」）即可发送。

（可选）若你有平台侧的「已申请/已开票」订单号快照，把 `invoice-status.json` 放到你的数据目录 `data/users/<你的ID>/` 下，导入时会自动同步订单级开票状态；不放则订单级开票状态全显示「未申请」。

### 第九步：部署验收（重要）

在控制台找一家**待开票金额小**的卖家（如几块钱的），点「催收消息」，确认：

- 你本机浏览器自动弹出工作标签页并打开该卖家的聊天页
- 消息发出且显示已读
- 看板进度面板显示 ✓ 成功（扩展弹窗里也能看到实时进度）

通过后再批量操作。

### 新电脑部署注意事项

1. **发送必须在本机浏览器**：催收消息从你自己的 Chrome/Edge 发出，服务器不代发；发送时那个浏览器要开着，关掉会中断任务（中断后可点「继续发送未完成」续跑）
2. **不能两台电脑同时跑**：同一 1688 账号两地同时操作会互踢登录态/触发风控。旧电脑不用了就关掉 server
3. **防火墙**：server.js 只监听本机 8787 端口，数据库只监听 127.0.0.1:3306。如果浏览器打不开控制台页面，检查安全软件是否拦截了 Node
4. **杀毒软件误报**：个别杀软会拦截 `keyboard.insertText` 之类的键盘模拟，若发送异常，把浏览器和项目目录加入信任区
5. **扩展兼容性**：仅桌面 Chrome / Edge（360 极速模式、IE、手机浏览器不支持，没有现代扩展体系）
6. **数据库开机自启**：便携版 MySQL 不会自动启动。把它做成快捷方式放进「启动」文件夹（`Win+R` → `shell:startup`），或每次用前跑一次 `scripts\mysql-start.bat`

## 日常操作（控制台页面）

### 看板页

顶部统计卡片：订单总金额、已开票金额（税务局）、待开票金额、人工确认已开票、已催收会员名（累计催收次数）、未匹配销方名称数。

**看板结构：一行 = 一家公司**。

> 发票是**按公司**开的，所以看板按公司合并（同一公司不管开了几个 1688 店铺都只有一行）。
> 点「**展开会员名(N)**」能看到这家公司名下的各个 **1688 会员名（店铺）**，每个店铺各自带：订单/金额、税务局已开票额、待开票金额、开票状态徽章、**催收按钮**和**订单明细**。
> 同一公司的多个会员名里，税务局发票额只挂在「主行」上（优先名称映射表登记的会员名），其他会员名标注「已计入「…」」——这是为了不把同一张发票算两遍。

**统计口径**（都从数据库算）：

- **已开票金额** = 税务局导出文件（`issued_invoice` 表）中该商家的「价税合计」明细总和（**含税**，与订单实付款同口径）
- **已开票数量（N 张发票）** = 税务局导出文件里该商家的**发票张数**，按**数电发票号码去重**
- **待开票金额** = 订单金额 − 已开票金额（不小于 0）；公司行按公司口径汇总，会员名按该店铺自己的订单算
- **催收次数 / 最近催收时间** = `send_log` 表统计，**只计成功**（`result='ok'`）。发送失败的尝试会记录在案（展开明细可见「失败」标记），但**不计入催收次数**、也**不作为最近催收时间**

> **「N 张发票」为什么比明细行数少？** 税务局导出是**一张发票上的每个货物各占一行**，同一张发票的多行**共用同一个「数电发票号码」**。统计时按号码去重，所以「一张票开了 2 个货物」会显示成 **2 行明细、1 张发票**（金额把 2 行都算进去了，只有张数去重）。
> 展开订单明细时，「已开票明细」段头会写明「X 行货物明细 · Y 张发票」，同属一张票的行会带灰色「同票」标记，可据此核对。

**催收口径（按会员名）**：点某个店铺的「催收消息」时——

- `{amount}` = **该会员名**的待开票金额
- `{orderId}` = **该会员名除「已开票」外的全部订单号**（平台已开票 + 人工确认的都排除）
- 也就是：每个店铺只收到自己店里的账，不会把同公司其他店铺的订单混进来

| 操作 | 说明 |
|---|---|
| **查看待开票** | 公司按待开票金额降序排列 |
| **展开会员名** | 点公司行的「展开会员名(N)」，列出该公司全部 1688 会员名（店铺），可勾选、可催收、可看各自订单 |
| **订单明细** | 点会员名旁的「订单明细」，按需从数据库加载该店铺的**订单明细**、**已开票明细**和**催收记录**（每次催收的时间/结果/来源，最近 50 次） |
| **标记已开票（人工确认）** | 展开订单明细后，每个订单行有「标记已开票」按钮；商家**一次性**线下开票覆盖多笔订单时，点明细顶部的「**全部标记已开票(N)**」一次搞定。标记后订单显示「已开票·人工」。点错可逐单或「取消人工确认(N)」整体回退到平台状态。人工确认不会被「重新导入数据」或平台状态刷新覆盖 |
| **催收消息** | 每个会员名的橙色按钮，点击即给该店铺发 3 条消息（模板 + 订单清单 + 提醒），同时记录催收时间、催收次数 +1 |
| **批量操作** | 勾选会员名（公司行的复选框会一次带出该公司全部可催收店铺）→ 顶部「发送催收消息 (N)」 |
| **重新导入数据** | 重新扫描 `data/完成订单`、`data/已开票订单` 下的 Excel **增量导入**：按订单号/行哈希去重，**数据库已有的跳过、只插入新数据**（已导入过的订单不会从看板消失；人工维护的名称映射、人工确认的开票状态都不受影响） |
| **筛选/搜索（可任意组合）** | 下拉「**催收状态**」= **已催收**（有成功催收记录的公司）/ 最近一周、半个月、一个月、三个月**未催收**（最近 N 天没有成功催收记录，含从未催收）；下拉「**开票状态**」= **已开票**（待开票金额 = 0）/ **未开票**（待开票金额 > 0）；搜索支持公司名和登录ID（会员名）。以上条件**任意组合**查询，筛选/搜索后自动回到第 1 页 |
| **排序** | 按**最近催收时间倒序**（刚催收过的排最前，从没催收过的沉底）；催收时间相同则按**待开票金额倒序** |
| **全选当前页** | 只勾选**当前分页**里公司的可催收会员名（不含其他分页）；「取消选择」一键清空 |
| **催收次数 → 历史记录** | 点公司行（或会员名行）的「催收次数」，弹窗查看该范围全部历史催收：**催收时间 / 结果 / 催收的总金额 / 催收的订单号**（多个订单号用「；」分隔）/**失败原因**。金额、订单号与失败原因是发送当时的快照，老记录（2026-10-12 之前）未留存、显示「—」 |
| **分页** | 表格下方分页条：每页 **10 / 20 / 50 / 100** 条，支持首页/上一页/下一页/末页；顶部统计卡始终按全部数据计算 |
| **进度面板** | 批量发送时顶部出现进度条和实时日志，显示「已完成/总数 · 当前卖家 · 成功/失败 · **已用时长 · 预计剩余**」（剩余按实际速率自校准）；随时可点「停止」，点后最多再等当前卖家发完（若正在等待间隔则立即停止）。**你本机浏览器的扩展弹窗里也有一个实时监控面板**（当前卖家 / 进度 / 成功失败计数 / 每家状态 + 停止按钮），两边数据同源 |

> **催收按钮的启用条件（会员名级）**：该店铺有待开票金额 **且** 还有未开票订单 **且** 有卖家会员名。订单全部开票（含人工确认）后按钮自动置灰，悬停可见原因。

> 「提交开票申请」按钮已按需求移除，不再提供该功能。

### 本机浏览器通道（唯一发送通道）

催收消息**只在你本机浏览器里发送**：服务器不保存你的 1688 登录态、不起服务器浏览器代发，全程接触不到你的账号密码。发送前先完成配对（只做一次）：

1. 在**你自己电脑的浏览器**（Chrome / Edge）里打开 1688 并登录（通常你本来就登录着，不用重登）。
2. 安装扩展：`chrome://extensions` → 打开「开发者模式」→「加载已解压的扩展程序」→ 选项目里的 `extension/` 目录。
3. 看板右上角点「**配对指引**」→「**生成配对码**」，复制**服务器地址 + 6 位配对码**（5 分钟内有效）。
4. 点扩展图标，填「服务器地址 + 配对码」→ 点「**连接**」。
5. 看板顶部状态条由灰变绿（显示「已连接 · 1688 已登录」）后，即可勾选卖家 → 发送。

发送时你的浏览器会弹出工作标签页逐家操作，**扩展弹窗里能看到实时监控面板**：当前卖家、进度条、成功/失败计数、每家状态，也可随时点「**停止**」。

> 兼容性：仅支持桌面 **Chrome / Edge**。360 极速模式、IE、手机浏览器**不支持**（没有现代扩展体系）。
> 发送中请保持该浏览器开着；关掉浏览器会中断任务。

**发到一半断了怎么办（断线续跑）**：重新打开浏览器、让扩展重新连上后，看板会出现黄色横幅「↻ 上次任务 #N 已中断：还有 X 家未发送」→ 点「**继续发送未完成**」即可接着发剩下的，**已经发成功的不会重发**。发送失败的会单独统计，可点「**重试失败项**」重发。不想处理可点「忽略」。
服务器重启导致任务状态丢失时也会自动标记为「已中断」，同样可以用这个横幅续跑。

### 发送前预览消息内容（可选）

不想真发一条消息就能核对内容时，用：

```bash
npm run msg:preview -- 会员名1 会员名2     # 例：npm run msg:preview -- 谨锐优选 德沃多肥料
```

会用看板的真实数据 + `config.json` 里的模板，渲染出**将要发送的每一条消息**（模板 / 订单清单分块 / 提醒），并显示 `{amount}`、`{orderId}` 清单条数与订单实付合计的对照。不联网、不发送。

### 已开票状态是怎么来的（订单为什么显示「已开票/已申请/未申请」）

`invoice_order.invoice_state` 有三个值：`none` 未申请 / `applying` 已申请 / `issued` 已开票。来源有两条通道：

**① 平台真实状态（快照文件，可选）**

1. 如果你有平台侧的「已申请/已开票」订单号快照（`invoice-status.json`），放到你的数据目录 `data/users/<你的ID>/` 下
2. 点看板「重新导入数据」时，末尾会自动把快照同步进数据库：`UPDATE invoice_order SET invoice_state=? WHERE order_no IN (...) AND invoice_state <> 'issued' AND state_source <> 'manual'`
   —— 已开票的不会回退；人工确认的不被覆盖
3. 没有快照文件时，订单级开票状态保持导入时的 `none`（显示「未申请」），以「② 人工确认」为准

> 历史上用 `node refresh-status.js` 自动拉取平台状态的脚本已随「服务端浏览器」一同移除（服务器不再启动任何浏览器）。需要平台状态时，按上面方式放快照文件即可，格式不变。

**② 人工确认（优先级最高）**

商家线下开票时，你在看板点「标记已开票」，写入 `invoice_state='issued'` + `state_source='manual'`。平台快照同步（①）和重新导入都跳过 `manual` 行，所以永远不会被覆盖；点「取消人工确认」则回退到快照同步出来的真实状态。

### 名称映射页

税务局导出的发票里写的是**销方名称**，跟 1688 订单里的**商家名称**往往不是同一个写法，必须靠这张映射表把两边对上，看板才能把发票金额统计到对应商家。

| 区域 | 说明 |
|---|---|
| **待人工比对** | 自动匹配不上的销方名称会列在这里，显示税号、发票行数、开票金额、备注线索。在右侧输入框里输入 1688 公司名（有下拉提示）→ 点「保存」，看板立即按新映射统计 |
| **忽略** | 若某个销方名称**确认没有**对应的 1688 商家，点该行的「忽略」：它会从待比对列表移除、不再参与自动匹配与看板统计（「未匹配销方名称」计数同步减少）。误忽略可在页面底部「已忽略」区点「恢复」找回 |
| **已维护映射** | 所有映射记录，标出「自动/人工」「已确认/待复核」，可删除（删除后该名称回到待人工比对），也可「忽略」 |
| **已忽略** | 默认收起，点击展开可查看全部被忽略的名称并「恢复」 |

两个列表都支持 **10 / 20 / 50 / 100 条/页** 分页（表格下方切换页码与每页条数）；看板公司列表同样支持分页。

自动匹配规则（导入时执行）：名称完全一致 → 名称互相包含（过滤过短名，防误判）→ 卖家会员名匹配 → 发票备注里的店铺名线索（如「1688 谨锐优选」）。

### 系统管理页（仅超级管理员）

可视化编辑，保存即生效，不用改代码：

- **用户管理（含开票抬头）**：新增 / 编辑 / 重置密码 / 禁用 / 删除账号。**登录账号 = 公司全称**；点某行「编辑」可改公司全称、纳税人识别号、收票邮箱（改了公司全称就等于改了登录账号）。催收话术里的 `{companyName}` / `{taxNo}` / `{email}` 按**每个账号自己的抬头**取值。**超级管理员（admin）是纯系统账号**——不承载看板数据、不维护抬头，其所在行只有「重置密码」
- **发送参数**：卖家间隔秒数（默认 15~30 秒，防限流的主要参数）；页面提示的预计总时长 ≈ 家数 ×（间隔均值 + 单家发送耗时约 15 秒）
- **消息模板**：三段消息的文案，可用变量 `{amount}`（待开票总金额）、`{orderId}`、`{companyName}`、`{taxNo}`、`{email}`，下方有实时预览

## 数据刷新（建议每周一次）

新订单成交、或税务局发票开出来后，看板不会自动更新，需要手动导入：

```
1. 从 1688 导出新的订单 xlsx → 放进 data/完成订单/
2. 从电子税务局导出全量发票 xlsx → 放进 data/已开票订单/
3. 看板点「重新导入数据」   （或命令行 node import-to-db.js）
4. 若之前有自动匹配不上的销方名称 → 去「名称映射」页人工补上
5. 想更新订单级开票状态 → 把 invoice-status.json 快照放进 data/users/<你的ID>/ 后重新导入（见「已开票状态是怎么来的」）
```

导入是**增量去重**：按订单号/行哈希判断，**数据库已有的行跳过、只插入新数据**，所以旧文件删掉后看板数据不会消失（只增不删）；人工维护的映射表、人工确认的开票状态都不受影响。

## 常见问题

**Q：看板显示"数据加载中"或提示数据库连接失败？**
数据库没启动。跑一次 `scripts\mysql-start.bat`，再重启 `node server.js`。

**Q：发送时能关浏览器窗口吗？**
不能，发送靠你本机浏览器弹出的工作标签页操作聊天。中断了也没关系，重新连上扩展后看板点「继续发送未完成」，已发的会自动跳过。

**Q：页面卡住/出现验证码？**
人工完成验证；白屏则在扩展弹窗点「停止」，确认浏览器里 1688 已登录后重新发送。

**Q：某家发送失败？**
日志里会有 ✗ 记录，看板进度面板与扩展弹窗都会标出失败的那家。催收记录同样会写入 `send_log`（`result='fail'`），次数列悬浮可见成功/失败拆分；可用「重试失败项」补发。

**Q：批量发到一半中断/提示 1688 掉线了？**
说明 1688 登录失效了（被踢下线/过期），任务会立即中止。在**你自己电脑的浏览器**里重新登录 1688（确认能打开聊天页），然后直接重发即可——**不需要向服务器上传任何登录态**，已发成功的会自动跳过。

**Q：点「配对指引」后要怎么操作？配对码是什么？**
不需要在服务器上登录，也不用扫码投屏。看板「配对指引」弹窗里点「**生成配对码**」会得到一个 6 位码（5 分钟有效），把它和服务器地址填进浏览器扩展，点「连接」，状态变绿即可发送。详见上文「**本机浏览器通道（唯一发送通道）**」。

**Q：扩展弹窗里能看到什么？**
实时监控面板：当前正在发送的卖家、第几家/共几家、进度条、成功/失败/待发送计数、每家卖家一个状态点，以及「停止」按钮。和看板进度面板数据同源。

**Q：想清掉某家的催收记录（重新催）？**
发送记录已存进数据库 `send_log` 表（一行 = 一次发送），删除对应行即可：
```sql
DELETE FROM send_log WHERE seller_login='卖家登录ID';
```

**Q：人工确认错了怎么撤销？**
展开该卖家的明细，在对应订单行点「取消人工确认」，会回退到平台快照同步出来的状态。

**Q：看板里「已开票金额（税务局）」是 0，但「订单开票状态」显示已开票？**
两个口径不同：前者来自税务局导出的发票数据（按名称映射后统计），后者是平台侧订单状态。税务局数据没导入或没映射上，前者就是 0。去「名称映射」页看有没有待人工比对的销方名称。

**Q：发票金额比订单金额还大？**
正常。税务局导出的是**历史全量**发票，而订单导出可能只覆盖某个时间段，卖方会被标记「发票额已覆盖订单」，该家待开票金额按 0 处理。

**Q：重新导入数据后，之前导入的订单会不见吗？**
不会。导入是**增量去重**：只插入数据库里没有的新订单，已有的全部保留；只有当你主动删库/删数据才会消失。

## 安全纪律

1. `config.json` 含账号与数据库密码，**不要截图外发、不要上传**。
2. **服务器不保存任何 1688 登录态**：登录与发送都发生在用户自己电脑的浏览器里，泄库也拿不到 1688 账号。
3. 卖家间隔是账号安全阀（默认 15~30 秒），别为了快调太激进（不建议低于 10 秒）。发送动作本身已优化到每家约 10~15 秒，20 家约 13 分钟。
4. 批量发送时你本机浏览器会自动弹出工作标签页逐家操作，属正常现象，勿手动干预。
