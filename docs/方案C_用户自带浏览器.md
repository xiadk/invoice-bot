# 方案C · 用户自带浏览器（本机执行发送）

> TL;DR：服务器只做编排，真正的 1688 登录与发送在**用户本机浏览器**里完成（浏览器扩展或常驻任务页）。服务器零浏览器开销；代价是强依赖客户端在线与用户环境。

## 0 约定与缩写

| 缩写 | 含义 |
|---|---|
| U | 用户 |
| EXT | 浏览器扩展（MV3）或「常驻任务页」 |
| ORCH | 服务端编排器（只下发任务、回收结果） |
| SS | 1688 登录态（**留在 U 本机，不上传**） |
| T | 一次发送任务 |
| C2S / S2C | 客户端→服务端 / 服务端→客户端（WS 消息） |

原则：SS 与密码不出本机；ORCH 不碰 U 的 1688 凭据；U 可随时暂停。

## 1 目标

- U 用账号密码登录系统看板（同方案B）。
- U 在本机浏览器内完成 1688 登录与发消息；**用 U 自己的 IP 与 SS**。
- 服务器不承载 1000 个浏览器，资源开销≈0。
- 适用「不愿把 1688 密码交给服务器 / 想用自己 IP」的场景。

## 2 拓扑

```
U本机: 浏览器(EXT/常驻页) ──发起──▶ 1688 聊天
           ▲   │  WS(C2S/S2C)
           │   ▼
         ORCH(服务端编排) ──▶ MariaDB(任务/结果)
```

注：**发送流量不经过服务器**，只在 U 本机与 1688 之间。

## 3 组件职责

| 组件 | 职责 | 形态 |
|---|---|---|
| EXT | 在 1688 页面执行登录检测与发送 | Chrome/Edge MV3 扩展，或常驻任务页 |
| ORCH | 任务下发、进度回收、结果入库 | 复用 `server.js` + WS |
| 看板 | 勾选卖家、下发 T、看进度 | `dashboard.html` |
| DB | 任务与结果 | 同方案B |

## 4 关键流程

### 4.1 绑定
1. U 登录系统 → 看板显示「连接本机浏览器」。
2. U 装 EXT（或打开常驻页）→ 用一次性配对码与 ORCH 建立 WS。
3. ORCH 记录 `uid ↔ 连接`，标记该 U「本机通道在线」。

### 4.2 1688 登录
1. U 在自己浏览器登录 1688（正常网页操作，SS 留在本机）。
2. EXT 仅上报「已登录/未登录」布尔；**不上报 Cookie**。

### 4.3 发送 T
1. 看板勾选卖家 → `POST /api/send` → ORCH 建 T → S2C 下发 `send_batch`。
2. EXT 逐个卖家：调 1688 聊天页操作/接口 → 回传 `sent {ok|fail, error}`。
3. ORCH 写 `send_log`（金额/订单号/结果）→ 前端进度更新。
4. 断线/离线：T 标记 `pending` 或 `aborted`，U 回来可续。

## 5 通信协议（WS）

| 消息 | 方向 | 关键字段 |
|---|---|---|
| `hello` | C2S | `pairCode`,`ua`,`extVer` |
| `ready` | S2C | `uid`,`serverTime` |
| `login_state` | C2S | `loggedIn:bool` |
| `send_batch` | S2C | `taskId`,`sellers[]`,`messages[]`,`gapMs` |
| `sent` | C2S | `taskId`,`seller`,`result`,`error?` |
| `progress` | S2C | `taskId`,`done`,`ok`,`fail` |
| `stop` | S2C | `taskId` |
| `ping/pong` | 双向 | 心跳，保活 |

约束：消息 ≤ 32KB；`send_batch` 分片；幂等键 `taskId+seller`。

## 6 安全与信任（关键）

| 项 | 做法 |
|---|---|
| 凭据 | 密码/Cookie **不出本机**，ORCH 不知情 |
| 权限最小 | EXT 仅申请 `*.1688.com` 域名权限 |
| 配对 | 一次性配对码，绑定单 U，可撤销 |
| 可审计 | 每步发送回执入库，可追溯 |
| 可退出 | U 可随时停 EXT / 断开连接 |
| 合规提示 | 首次说明：仅代发催收，不采集其他数据 |

## 7 浏览器兼容性

| 浏览器 | 承载 EXT | 说明 |
|---|---|---|
| Chrome / Edge | ✅ | MV3 可用（推荐） |
| Firefox | ✅ | 需签名分发 |
| Safari | ⚠️ 有限 | 需 Xcode 打包，门槛高 |
| 360 极速模式 | ⚠️ 不保证 | 有自有商店/策略，实测为准 |
| 360 兼容模式 / IE | ❌ | 无现代扩展体系，跑不起来 |
| 手机浏览器 | ❌ | 无法稳定后台自动化 |

基线结论：**EXT 仅面向桌面 Chrome/Edge/Firefox**；仅看板可放宽（见方案B）。

## 8 部署

| 服务 | 说明 |
|---|---|
| ORCH | 复用 `server.js` + WS，加「本机通道」模块 |
| EXT 分发 | Chrome/Edge 商店 或 企业内分发（.crx / 策略）|
| 常驻页备选 | `agent.html`：需 U 保活标签页，免装扩展 |
| DB | 同方案B，新增 `task` 表 |

## 9 与方案B对比

| 维度 | 方案B 服务端浏览器池 | 方案C 用户自带浏览器 |
|---|---|---|
| 浏览器在哪 | 服务器 | U 本机 |
| 服务器资源 | 中（固定槽位 B） | ≈0 |
| 出网 IP | 服务器 IP | U 自己的 IP（风控更友好）|
| 凭据归属 | SS 存服务器 | SS 留在本机（更安全）|
| 是否需 U 在线 | 否（可离线代发）| **是**（关机即断）|
| 环境可控性 | 高（自己排障）| 低（用户机器不可控）|
| 用户体验 | 无感 | 需装扩展/常开页面 |
| 适用 | 通用主通道 | 高级用户/可选通道 |

## 10 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| U 离线/关机 | T 中断 | 任务可续传；回来看板恢复 |
| 环境差异 | 发不出去 | 预检自检页 + 明确报错码 |
| 企业禁装扩展 | 无法使用 | 提供「常驻页」备选通道 |
| 商店审核慢 | 升级滞后 | 首版走企业内分发 |
| 浏览器安全限制 | 注入失败 | 仅用官方接口/最小 DOM 操作 |
| 信任门槛 | 用户不接受 | 明示权限范围 + 可随时退出 |

## 11 验收

- [ ] U 装 EXT/开常驻页 → 成功配对并在线。
- [ ] U 本机登录 1688 → EXT 上报已登录（不传 Cookie）。
- [ ] 看板下发 T → 本机发送 → 结果写入 `send_log`。
- [ ] 断线重连后可续跑未完成 T。
- [ ] ORCH 全程接触不到 1688 凭据。
- [ ] 不支持的浏览器给出明确提示。
